# Persistence

> Read this before: you touch `infrastructure/`, table definitions, repositories, or migrations.
> Drizzle imports are enforced by dependency-cruiser. Destructive migrations are caught by `pnpm check:migrations`.
> Part of the reusable `ddd-nextjs` conventions profile. Keep project-specific facts out of this file.

- Postgres with Drizzle. Drizzle may be imported only inside `infrastructure/`
  (and `src/composition/` for wiring). Table definitions live in `*.model.ts`.
- A repository maps rows to aggregates with `reconstitute` through a mapper,
  and saves one aggregate per transaction.
- Migrations are generated by `pnpm db:generate` into `drizzle/` and committed. Never edit a
  migration that has been merged, and never hand-edit generated snapshots.
- Migrations must be backward compatible: new tables, and new columns that are
  nullable or have defaults. The previous version of the app must keep working
  against the new schema.
- Anything else (drop, rename, type change, data rewrite) is a "Stop and ask".
  `pnpm check:migrations` flags `DROP`, `TRUNCATE`, `DELETE`, `UPDATE`, renames, type changes,
  `SET NOT NULL`, and `ADD COLUMN ... NOT NULL` without a `DEFAULT` as `NEEDS_HUMAN`.
- Migration files get timestamp prefixes (`migrations.prefix` in `drizzle.config.ts`), so
  migrations generated by parallel agents do not collide.
- Integration tests run against a real Postgres (service container in CI,
  `docker compose` locally), never against a mocked database.
